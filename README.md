# 📚 AI Study Assistant

A **local, privacy-first AI-powered Document Question Answering system** built with RAG (Retrieval-Augmented Generation).

Upload your PDFs (textbooks, notes, question papers) and ask questions — the AI answers **only from your uploaded documents**, never from general knowledge.

## Features

- 📄 **PDF Upload & Processing** — Extract text, chunk, and embed automatically
- 🔍 **Semantic Search** — Find relevant content using vector similarity
- 🤖 **Local LLM** — Answers generated by a local model via Ollama (no API keys needed)
- 🛡️ **Hallucination Control** — Rejects low-confidence retrievals, refuses to guess
- 📖 **Source Citations** — Every answer shows the document name and page number
- 📚 **Multi-Document Support** — Upload multiple PDFs, search one or all
- 🎯 **Answer Modes** — Simple, Exam, Short, Detailed, or Bullet Points
- 🔒 **Privacy-First** — Everything runs locally, no data sent to the cloud

## Quick Start

### 1. Prerequisites

- Python 3.10+
- [Ollama](https://ollama.com/download) installed and running

### 2. Setup

```bash
# Clone/navigate to project
cd "llm project"

# Create virtual environment
python -m venv venv
.\venv\Scripts\Activate.ps1  # Windows PowerShell

# Install dependencies
pip install -r requirements.txt

# Pull a local LLM model
ollama pull mistral
```

### 3. Configure

Copy `.env.example` to `.env` and edit as needed:

```bash
copy .env.example .env
```

Key settings:
- `OLLAMA_MODEL` — Which local model to use (default: `mistral`)
- `CHUNK_SIZE` — Characters per chunk (default: `800`)
- `SIMILARITY_THRESHOLD` — Minimum relevance score (default: `0.3`)

### 4. Run

```bash
# Make sure Ollama is running
ollama serve

# Start the application (in another terminal)
uvicorn backend.main:app --reload --port 8000
```

Open `http://localhost:8000` in your browser.

## How It Works

```
Upload:   PDF → Text Extraction → Chunking → Embeddings → ChromaDB
Question: Query → Embed → Search ChromaDB → Filter by Score → LLM → Grounded Answer
```

1. **Upload a PDF** — Text is extracted, split into chunks, converted to embeddings, and stored
2. **Ask a question** — The question is embedded and compared against stored chunks
3. **Retrieve relevant chunks** — Top-K most similar chunks are found
4. **Filter by threshold** — Low-relevance chunks are discarded (hallucination guard)
5. **Generate answer** — The local LLM answers using ONLY the retrieved context
6. **Show sources** — Document name + page number cited with every answer

## API Endpoints

| Method | Endpoint | Purpose |
|--------|----------|---------|
| `GET` | `/api/health` | System health check |
| `POST` | `/api/upload` | Upload and process a PDF |
| `GET` | `/api/documents` | List uploaded documents |
| `DELETE` | `/api/documents/{id}` | Delete a document |
| `POST` | `/api/chat` | Ask a question (RAG) |

## Configuration

All settings are in `.env`:

| Variable | Default | Description |
|----------|---------|-------------|
| `OLLAMA_MODEL` | `mistral` | Local LLM model name |
| `EMBEDDING_MODEL` | `all-MiniLM-L6-v2` | Sentence transformer model |
| `CHUNK_SIZE` | `800` | Max characters per chunk |
| `CHUNK_OVERLAP` | `100` | Overlap between chunks |
| `TOP_K` | `5` | Number of chunks to retrieve |
| `SIMILARITY_THRESHOLD` | `0.3` | Minimum relevance score |
| `MAX_UPLOAD_SIZE_MB` | `50` | Maximum upload file size |
